# Supabase CMS

This project is a small CMS built with React, Vite, Supabase Auth, and Supabase Postgres.

## Structure

```text
financialservice/
|-- client/
|   |-- src/
|   |   |-- components/
|   |   |   |-- Dashboard.jsx
|   |   |   `-- Login.jsx
|   |   |-- admin.jsx
|   |   |-- App.jsx
|   |   |-- main.jsx
|   |   |-- styles.css
|   |   `-- supabase.js
|   |-- .env.example
|   |-- index.html
|   |-- package.json
|   `-- vite.config.js
|-- package.json
`-- vercel.json
```

There is no required custom backend in this repo. The app talks directly to Supabase.

## Environment Variables

Create `client/.env` from `client/.env.example`:

```env
VITE_SUPABASE_URL=<your_supabase_url>
VITE_SUPABASE_ANON_KEY=<your_anon_key>
VITE_LOGIN_LOOKUP_TABLES=users
```

`VITE_LOGIN_LOOKUP_TABLES` is optional. It controls which tables are checked for `username -> email` lookup before signing in with Supabase Auth.

## Supabase Setup

### 1. Authentication

In Supabase:

1. Create a project.
2. Go to `Authentication`.
3. Enable `Email/Password` sign-in.
4. Create an admin user in Supabase Auth with an email and password.

### 2. Database Tables

Run this SQL:

```sql
create table if not exists public.users (
  id bigint generated by default as identity primary key,
  username text not null unique,
  email text not null unique
);

create table if not exists public.landing_page_config (
  id bigint generated by default as identity primary key,
  site_name text not null,
  logo_url text,
  description text not null
);

insert into public.landing_page_config (id, site_name, logo_url, description)
values (1, 'My CMS Site', '', 'Edit this content from the admin dashboard.')
on conflict (id) do nothing;

insert into public.users (username, email)
values ('admin', 'your-auth-email@example.com')
on conflict (username) do nothing;
```

The `users.email` value must match a real user in Supabase Auth.

### 3. Row Level Security

Run this SQL:

```sql
alter table public.landing_page_config enable row level security;
alter table public.users enable row level security;

create policy "Public can read landing page config"
on public.landing_page_config
for select
to anon, authenticated
using (true);

create policy "Authenticated users can insert landing page config"
on public.landing_page_config
for insert
to authenticated
with check (true);

create policy "Authenticated users can update landing page config"
on public.landing_page_config
for update
to authenticated
using (true)
with check (true);

create policy "Public can read user login mappings"
on public.users
for select
to anon, authenticated
using (true);
```

## Local Development

Install dependencies:

```bash
npm run install:client
```

Run the app:

```bash
npm run dev:client
```

Open `http://localhost:5173`.

## CMS Behavior

- `/` renders the landing page from `landing_page_config`.
- `/admin` shows the login form for logged-out users.
- `/admin` accepts either a username or an email.
- Authenticated users can update the site name, logo URL, and description.
- Content updates are saved into `landing_page_config`.

## Vercel Deployment

Recommended Vercel settings:

- `Root Directory`: `client`
- `Build Command`: `npm run build`
- `Output Directory`: `dist`

Environment variables required in Vercel:

- `VITE_SUPABASE_URL`
- `VITE_SUPABASE_ANON_KEY`
- `VITE_LOGIN_LOOKUP_TABLES` (optional)
